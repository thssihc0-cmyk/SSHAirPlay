## 1. 产品目标

做一个 **iOS / iPadOS 原生 SSH 服务器管理工具**。手机（或 iPad）是唯一操作面；通过 **AirPlay 或 HDMI 外接屏** 提供 **独立第二屏 UI**，用于放大终端、监看多会话。

### 1.1 成功标准

1. 无外接屏时，作为完整 SSH 客户端可用。
2. AirPlay 到 Apple TV 后，电视显示 **与手机不同的专用界面**，不是屏幕镜像。
3. 在手机打字时，本机终端立刻回显；电视异步同步同一会话，允许短暂落后。
4. 断开外接屏后，手机继续工作，不崩溃、会话尽量保持。

### 1.2 非目标（第一版明确不做）

- 独立 tvOS App
- 控制中心「屏幕镜像」作为正式投屏方案
- 在 Apple TV / 遥控器上输入命令
- SFTP、端口转发、VPN、跳板机（ProxyJump）
- 后台长期保活 SSH（iOS 系统不允许可靠实现）
- 容器编排、Web 面板、IDE 级编辑器

## 2. 术语

| 术语 | 含义 |
|------|------|
| 本机屏 | iPhone / iPad 内建屏幕，可交互 |
| 外接屏 / 第二屏 | AirPlay（Apple TV 等）或 HDMI 连接的显示器，**不可交互** |
| 镜像 | 系统把本机屏画面原样复制到外接屏。第一版正式体验 **禁止** 以此为投屏方案 |
| 第二屏模式 | App 向外接屏 Scene 挂载独立 `UIWindow`，系统停止镜像，显示专用 UI |
| 会话（Session） | 一次 SSH 交互式 Shell（PTY），有独立终端缓冲 |
| 主机（Host） | 一条可连接的服务器配置（地址、端口、用户、认证） |
| 控制台布局 | 外接屏连上后，本机自动切换的紧凑操作界面 |

## 3. 用户与场景

### 3.1 目标用户

- 用 iPhone / iPad 管理 Linux / Unix 服务器的开发、运维人员
- 需要把终端展示给旁边的人看（演示、结对、会议室）
- 需要同时盯多台机器或长任务输出（编译、部署、日志）

### 3.2 主路径

**P1 无外接屏 SSH（必测）**

1. 打开 App，添加主机（地址、端口、用户、密钥或密码）
2. 连接，进入终端
3. 输入命令，看到正确回显
4. 可开第二个会话并切换
5. 断开或返回主机列表

**P2 AirPlay 第二屏（必测，核心差异化）**

1. App 在前台，已有至少一个会话（或先连上再开会话）
2. 用户通过控制中心或 App 内入口将设备投到 Apple TV
3. 电视出现 **专用大屏终端 / 宫格**，不是主机列表或键盘的镜像
4. 本机切到控制台布局：缩小终端 + 键盘 + 附加键
5. 本机打字立刻出字；电视随后显示同一输出
6. 断开 AirPlay，本机恢复完整布局，会话不因断开外屏而主动断开

**P3 多会话监看**

1. 本机同时有 2–4 个会话
2. 外接屏以宫格显示各会话输出
3. 当前焦点会话在电视上有明确高亮
4. 本机切换焦点，电视高亮跟随

**P4 外接屏异常**

1. AirPlay 中途断开：本机提示「第二屏已断开」，恢复完整布局
2. 用户切到后台：按系统行为会话可能挂起或断开；回到前台提示状态并提供重连
3. 从未连接外接屏：所有 SSH 功能完整，不出现「请连接电视」才能用的阻断

## 5. 功能需求

### 5.1 主机管理

**FR-H01** 用户可创建主机，字段如下。

| 字段 | 必填 | 说明 |
|------|------|------|
| 显示名 | 是 | 列表展示 |
| 主机地址 | 是 | 域名或 IP |
| 端口 | 是 | 默认 22 |
| 用户名 | 是 | |
| 认证方式 | 是 | `privateKey` / `password` |
| 私钥引用 | 密钥时必填 | 只存 Keychain 标识，不存明文到数据库 |
| 密码引用 | 密码时必填 | 只存 Keychain 标识 |
| 备注 | 否 | |
| 分组 | 否 | 第一版可用简单字符串标签 |

**FR-H02** 列表展示显示名、地址、最近连接状态（未连接 / 已连接 / 失败）。

**FR-H03** 支持编辑、删除。删除主机时，若该主机仍有活动会话，须先确认并断开会话。

**FR-H04** 私钥导入：从文件（`.pem` / OpenSSH 私钥）或粘贴文本。导入后写入 Keychain，沙盒内不保留明文副本。

**FR-H05** 密码不出现在日志、截屏以外的持久化存储中（截屏由系统处理，App 不额外写入）。

### 5.2 SSH 连接与会话

**FR-S01** 连接流程：解析主机 → 建立 TCP → SSH 握手 → 认证 → 申请 PTY → 启动用户 shell。

**FR-S02** PTY 类型使用 `xterm-256color`（若服务端不支持则回退 `xterm`）。

**FR-S03** 本机终端视图尺寸变化时，必须向服务端发送窗口尺寸更新（rows/cols）。外接屏尺寸变化 **不** 单独改 PTY 尺寸，以免两边错位；PTY 尺寸始终跟本机终端。

**FR-S04** 会话状态机见第 8 节。UI 必须反映：`idle` / `connecting` / `authenticating` / `connected` / `reconnecting` / `failed` / `closed`。

**FR-S05** 认证失败须给出可读原因（权限拒绝、密钥不匹配、主机不可达、超时），禁止只显示「失败」。

**FR-S06** 同一主机允许开多个会话。

**FR-S07** 第一版并发会话上限为 **4**。达到上限时禁止新建，提示关闭已有会话。

**FR-S08** 用户主动断开：发送 EOF / 关闭通道，释放资源，从活动列表移除。

**FR-S09** 网络错误或对端关闭：进入 `failed` 或 `reconnecting`。前台时自动重连最多 **3** 次，间隔 1s / 2s / 4s。三次失败后停在 `failed`，提供手动重连。

**FR-S10** App 进入后台：不承诺保持 TCP。回到前台后检测通道，已断则标 `failed` 并提示重连。不得静默假装仍连接。

### 5.3 本机终端

**FR-T01** 使用 VT/xterm 兼容渲染（推荐 SwiftTerm），支持：

- 常见 CSI 序列、颜色（256 / truecolor 尽力而为）
- 滚动回看，缓冲至少 **5000** 行
- 长按选区、复制到剪贴板
- 粘贴到终端（需确认多行粘贴，避免误执行）

**FR-T02** 附加键栏（本机常驻，外接屏控制台布局时必须可见）：

`Esc` `Tab` `Ctrl` `Alt` `↑` `↓` `←` `→` `` ` `` `-` `/`

`Ctrl` 为粘滞修饰：点一次后下一次字母以控制字符发送，然后自动松开。

**FR-T03** 软件键盘弹出时，终端可视区域缩小，底部不被遮挡；光标行尽量可见。

**FR-T04** 输入路径：按键 → 本机终端立刻本地回显（由 PTY echo 或客户端处理，以实际 SSH echo 为准）→ 字节写入 SSH 通道。**禁止**等外接屏渲染完成再显示。

### 5.4 多会话 UI（本机）

**FR-M01** 活动会话以标签或底部条展示，可切换焦点。

**FR-M02** 非焦点会话仍接收服务端输出并写入各自缓冲。

**FR-M03** 关闭标签即断开该会话。

### 5.5 AirPlay / 外接第二屏

本节为差异化核心，实现必须遵守第 7 节技术约束。

**FR-E01** App 采用 Scene 生命周期。外接屏使用 role：`UIWindowScene.Role.windowExternalDisplayNonInteractive`。

**FR-E02** 向外接屏 Scene **挂载专用 `UIWindow` 并显示内容** 后，系统停止镜像。这是「非镜像」的唯一正式实现。

**FR-E03** 外接屏 **不可交互**（无触摸、无遥控器点击处理）。所有输入只在本机。

**FR-E04** 无外接屏时 App 必须完整可用。第二屏是增强，不是前置条件。

**FR-E05** iOS 版本差异：

| 系统 | 行为 |
|------|------|
| iOS 17–26 | 外接屏连接时系统会连接 external display Scene；App 在 `scene(_:willConnectTo:)` 挂窗口即进入第二屏模式 |
| iOS 27+ | 必须注册 Scene Accessory（`UISceneAccessory.externalNonInteractive` 或 SwiftUI `ExternalNonInteractiveAccessory`），否则系统会走镜像 |

第一版最低系统：**iOS 17**。对 iOS 27+ 必须走 Accessory，避免升级后变回镜像。

**FR-E06** 外接屏布局（用户可在本机切换，默认随会话数）：

| 模式 ID | 名称 | 规则 |
|---------|------|------|
| `focus` | 当前会话大屏 | 只显示焦点会话，字号大，深色高对比 |
| `grid` | 多会话宫格 | 2 路用 1×2；3–4 路用 2×2；焦点会话边框高亮 |

无活动会话时，外接屏显示等待页：产品名 +「在 iPhone 上连接主机」+ 连接状态，**不要**镜像本机主机列表。

**FR-E07** 外接屏终端：

- 只读，不弹出键盘
- 字号不小于 **18pt**（按 1080p 基准，按屏宽缩放）
- 深色背景，光标可见
- 不随外接屏改 PTY 尺寸；可用 letterbox / 裁切右侧空列，优先保证可读而不是填满
- 允许比本机滞后；目标平均滞后 **< 500ms**（受 AirPlay 链路限制，不作为硬失败，但架构上不得再叠加额外全缓冲等待）

**FR-E08** 本机在第二屏 **已呈现** 时自动进入控制台布局：

- 顶栏：第二屏已连接指示（非镜像）+ 断开/布局切换
- 中部：缩小的焦点终端（仍可操作）
- 底部：附加键 + 系统键盘

第二屏断开后恢复完整布局。

**FR-E09** 用户可主动退出第二屏模式（卸载外接 `UIWindow` / 取消 Accessory）。退出后系统可回退为镜像；产品文案需说明「将恢复系统镜像」。默认进入投屏时应 **自动进入第二屏模式**，避免用户先看到镜像。

**FR-E10** App 内提供投屏入口（`AVRoutePickerView` 或等效系统控件），文案为「在电视上显示」，不要写成「镜像」。

**FR-E11** 外接屏安全区、分辨率、超宽屏按该 `UIWindowScene` 的 `screen` 适配，禁止写死 1920×1080。

**FR-E12** 外接屏显示连接状态条：主机名、会话状态、重连中、已断开。状态以大字号展示，不只依赖本机 toast。

### 5.6 设置与关于

**FR-C01** 可设置：终端字号（本机）、配色（深色默认）、多行粘贴确认开关。

**FR-C02** 关于页包含：版本号、开源组件致谢（SwiftTerm、SSH 库等）。

## 6. 非功能需求

### 6.1 性能

| ID | 要求 |
|----|------|
| NF-P01 | 本机按键到终端出现字形：目标 **< 32ms**（一帧内），不含网络 RTT |
| NF-P02 | 高速输出（如 `cat` 大文件）本机不永久卡死 UI；可丢帧渲染，但缓冲不丢数据 |
| NF-P03 | 4 路会话同时输出时，本机滚动仍可操作 |
| NF-P04 | 外接屏渲染与本机解耦：外接屏掉帧不得阻塞 SSH 读写 |

### 6.2 安全

| ID | 要求 |
|----|------|
| NF-S01 | 私钥、密码只进 Keychain，accessibility 使用 `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`（或同等「仅本机」策略） |
| NF-S02 | 主机列表可用 SwiftData / 文件；**禁止**把密钥写入该库 |
| NF-S03 | 调试日志不得打印密码、私钥、完整命令行里的口令 |
| NF-S04 | 第一版不做已知主机指纹严格策略也可上线，但须在连接 UI 提示「未校验主机密钥」；第二版补 known_hosts |
| NF-S05 | 不把会话内容上传任何服务器。本产品无账号系统 |

### 6.3 系统与兼容

| ID | 要求 |
|----|------|
| NF-C01 | 最低 iOS 17.0，iPhone + iPad |
| NF-C02 | 必测：iPhone + Apple TV AirPlay |
| NF-C03 | 选测：iPad + HDMI 转接器 |
| NF-C04 | 横竖屏：iPhone 终端以竖屏为先，横屏可用；外接屏按电视横向 |
| NF-C05 | 本地网络权限：第一版若不做扫描可不申请；仅 TCP 连用户填写的地址 |

### 6.4 后台与生命周期

| ID | 要求 |
|----|------|
| NF-L01 | 不申请无必要的后台模式来「保活 SSH」 |
| NF-L02 | `scenePhase` / App 状态变化必须更新会话健康检查 |
| NF-L03 | 外接屏 Scene 断开时只拆第二屏 UI，不主动拆 SSH |

### 6.5 合规（上架）

| ID | 要求 |
|----|------|
| NF-G01 | SSH 使用非豁免加密，填写出口合规；`ITSAppUsesNonExemptEncryption` 按实际问卷结果配置 |
| NF-G02 | 隐私政策说明：数据仅存本机 Keychain / 本地库 |
| NF-G03 | 不声称可突破设备管理或用于未授权访问 |

### 6.6 体验文案原则

- 第二屏相关用语使用「在电视上显示 / 第二屏」，避免「投屏镜像」
- 断线、重连、外屏断开都要有 **人话** 状态，不用原始 errno 作为唯一文案

## 7. 技术规格

### 7.1 推荐技术栈（第一版绑定）

| 层 | 选择 | 备注 |
|----|------|------|
| 语言 | Swift 5.9+ | |
| UI | SwiftUI 为主 | 终端、外接屏窗口可用 UIKit 承载 |
| 终端 | SwiftTerm | 不从零写 VT |
| SSH | Citadel（SwiftNIO SSH） | 备选 NMSSH，选定后不混用 |
| 主机存储 | SwiftData | |
| 密钥 | Keychain Services | |
| 外接屏 | UIKit Scene + 可选 SwiftUI Accessory | 见 FR-E05 |
| 架构 | MVVM + 单一 `SessionStore` | 双屏只读同一 Store |

禁止用 Flutter / React Native 做第一版终端与外接屏。

### 7.2 逻辑架构

```
                    ┌─────────────────────────────────────┐
                    │           SessionStore               │
                    │  hosts, sessions, focusSessionID     │
                    │  每会话：状态、终端缓冲、SSH 通道      │
                    └───────────────┬─────────────────────┘
                                    │ 观察 / 订阅
              ┌─────────────────────┴─────────────────────┐
              ▼                                           ▼
   ┌─────────────────────┐                     ┌─────────────────────┐
   │  本机 Scene          │                     │  外接屏 Scene         │
   │  windowApplication  │                     │  ExternalNonInteractive│
   │  可交互              │                     │  只读、全屏            │
   │  主机 / 终端 / 键盘   │                     │  focus / grid / 等待  │
   └─────────────────────┘                     └─────────────────────┘
              ▲                                           ▲
              │ 输入只走这里                                │ 禁止输入
              ▼                                           │
        SSH 通道 I/O  ◄────────────────────────────────────┘
                    （输出扇出到各会话缓冲，两套 View 各自渲染）
```

### 7.3 关键实现规则

1. **一份缓冲，两套渲染**：每个会话一个终端模型（字符网格 / SwiftTerm `Terminal`）。本机与外接屏都绑定它。禁止外接屏再开一条 SSH。
2. **PTY 尺寸 = 本机终端**：外接屏只做显示变换。
3. **挂窗口 = 非镜像；卸窗口 = 可能回到镜像。**
4. 外接屏 `UIWindow` 不要 `makeKey()` 抢本机第一响应者，以免键盘异常。
5. SSH 读写在后台队列；切回主线程只更新 UI 快照。高速输出要节流 UI 刷新（例如每帧最多一次），缓冲仍完整写入。

### 7.4 Info.plist / Scene 配置要点

- 启用 Application Scene Manifest
- iOS 17–26：为 External Display Session Role 配置 Scene Configuration（或在 `configurationForConnecting` 返回）
- iOS 27+：不以「仅 plist 配了 role」代替 Accessory 注册
- 需要时声明本地网络；第一版可不声明
- 加密合规键按 NF-G01

### 7.5 目录建议（实现时）

```
App/
  App.swift / SceneDelegate
  Hosts/
  Session/
  Terminal/
  ExternalDisplay/
  Keychain/
  Models/
```

具体工程名可在创建 Xcode 项目时确定。

## 8. 状态机

### 8.1 会话

```
                    用户连接
   idle ──────────────────► connecting ──► authenticating ──► connected
     ▲                         │                 │                │
     │                         ▼                 ▼                │
     │                      failed ◄─────────────┘                │
     │                         ▲                                  │
     │                         │ 网络断开（前台）                    │
     │                         │                                  ▼
     │                    reconnecting ◄──────────── connected 异常
     │                         │
     │                         └── 超过 3 次 ──► failed
     │
     └── 用户关闭 / 主动断开 ◄──── connected / failed / reconnecting
                              进入 closed，然后从列表移除（或回 idle）
```

规则：

- `connecting` / `authenticating` 可取消 → `closed`
- `connected` 时外接屏断开 **不** 改变该状态
- 后台唤醒发现已断 → `failed`（不自动在后台重连）

### 8.2 外接屏

```
  无外接屏 ──连接 AirPlay/HDMI──► 系统提供 Scene
                                      │
                         App 挂载 UIWindow / Accessory
                                      ▼
                               第二屏已呈现
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
                 等待页            focus 大屏          grid 宫格
                 （无会话）         （有焦点会话）      （≥2 会话，用户选宫格）
                    │                 │                 │
                    └──────── 卸载窗口 / 物理断开 ───────┘
                                      ▼
                                 无外接屏
                          （系统可能恢复镜像，App 不控制镜像内容）
```

**默认策略：** Scene 一可用就挂窗口，避免闪一下镜像。无会话用等待页。

## 9. 数据模型（逻辑）

```
Host
  id: UUID
  name: String
  hostname: String
  port: Int
  username: String
  authMethod: privateKey | password
  keychainAccount: String    // 指向 Keychain
  note: String?
  tag: String?
  createdAt, updatedAt: Date

Session
  id: UUID
  hostID: UUID
  state: SessionState
  title: String              // 默认 host.name，后续可改
  terminal: TerminalBuffer   // 内存，不持久化
  createdAt: Date

AppSettings
  fontSizeLocal: Double
  colorScheme: dark | light | system
  confirmMultilinePaste: Bool
  externalLayout: auto | focus | grid
```

会话与终端缓冲 **不落盘**。主机配置落盘。密钥只在 Keychain。

## 11. 错误与提示文案（规范级）

| 情况 | 本机 | 外接屏 |
|------|------|--------|
| 无法连接主机 | 「无法连接到 {host}，请检查网络和地址」 | 状态条：连接失败 |

| 第二屏已连接 | 「已在电视上显示（非镜像）」 | — |
| 第二屏断开 | 「电视已断开，可继续在本机操作」 | 画面消失（系统） |
| 会话数达上限 | 「最多同时 4 个会话」 | 不变 |
| 从后台回来已断 | 「连接已中断，点此重连」 | 若仍呈现：已断开 |

## 12. 测试规格

### 12.1 功能验收（必须全部通过）

1. 无外接屏：密钥登录成功，`ls`、`htop`、中文、方向键、Ctrl+C 行为正确。
2. 密码登录成功（测试机）。
3. 错误地址 / 错误密钥有明确失败文案。
4. 4 路会话切换，非焦点会话输出不丢失。
5. 关闭会话后连接释放（服务端侧可观察）。
6. AirPlay 到 Apple TV：电视 UI ≠ 本机 UI。
7. 电视无主机列表、无软件键盘。
8. 本机打字即时；电视内容为同一会话。
9. 2 路以上可切宫格，焦点高亮正确。
10. 断开 AirPlay：本机布局恢复，SSH 不因断开外屏而主动断。
11. 无会话时投屏：电视为等待页，不是镜像。
12. 杀进程再开：主机还在，会话不恢复（符合「缓冲不落盘」）。

### 12.2 回归

- 键盘遮挡、旋转、分屏（iPad）
- 投屏过程中新建 / 关闭会话
- iOS 17 与最新系统各测一次外屏接入（有设备条件时）

### 12.3 不测 / 已知限制（写入发布说明）

- App 在后台时不保证 SSH 不断
- AirPlay 链路延迟导致电视回显慢于本机
- 外接屏无法触摸操作
- 未做主机密钥固定（TOFU）时存在中间人风险，发布说明需提及

## 14. 风险与决策记录

| 风险 | 影响 | 决策 |
|------|------|------|
| AirPlay 延迟 | 只看电视打字体验差 | 本机必须保留即时终端 |
| iOS 27 API 变化 | 升级后变回镜像 | 双路径：旧 Scene + 新 Accessory |
| 后台杀连接 | 用户以为还连着 | 前台健康检查 + 明确文案，不保活 |
| 外屏改 PTY 尺寸 | 本机与电视错位 | PTY 只跟本机 |
| 镜像被用户从控制中心打开 | 未挂窗口时会镜像 | 默认自动挂窗口进入第二屏模式 |
